# Reverse-engineer sequences + serial/identity columns — design

- **Date:** 2026-06-16
- **Status:** approved (design)
- **Target release:** part of minor v0.7.0 (bundled with roles)
- **Builds on:** the reverse engine + functions/procedures + roles

## Goal

Reverse-engineer **standalone sequences**, and make **serial / identity columns** round-trip
correctly. These are coupled: a `serial`/`IDENTITY` column auto-creates a sequence that is
*owned by* the column, so excluding column-owned sequences (correct) is only safe if the
owning column re-creates its sequence on apply.

## Two coupled pieces

### (a) Standalone sequences → new `EntityType::Sequence`

- A sequence is `pg_class.relkind = 'S'`. It is **column-owned** when `pg_depend` has a row
  `(classid=pg_class, objid=seq, refclassid=pg_class, refobjsubid>0, deptype IN ('a','i'))`
  (`a` = serial, `i` = identity). **Only non-owned (standalone) sequences are emitted** as
  `EntityType::Sequence`; column-owned ones are excluded (reproduced via their column — see (b)).
- New entity type wired through:
  - `entity.rs`: `EntityType::Sequence`, `tag() == "sequence"`, `has_schema() == true`,
    `from_folder_name` accepts `"sequence"`/`"sequences"`.
  - `design.rs`: add a `sequences` bucket to the apply-order grouping and place it
    **before tables** (a column `DEFAULT nextval('seq')` referencing a standalone sequence
    needs the sequence to exist first). New order:
    `schemas → extensions → roles → sequences → enums → tables → views → functions → externals`.
  - `reverse.rs`: add `EntityType::Sequence` to `MANAGED_KINDS`. `entity_path` already maps it
    (`has_schema`) → `ddl/sequence/<schema>/<name>.ddl`. Included **by default** (DB-owned,
    not opt-in, unlike roles).
- **Introspect** (`introspect_sequences`): from `pg_sequences` (PG ≥ 10) + `pg_sequence`/
  `pg_class` for the type, in selected schemas, excluding column-owned. Capture: start value,
  increment, min, max, cache, cycle, data type.
- **Emit** (`emit_sequence`): reconstruct
  `CREATE SEQUENCE "s"."n" AS <type> INCREMENT BY <i> MINVALUE <m> MAXVALUE <M> START WITH <s> CACHE <c> [CYCLE];`
  (omit `AS bigint`/default min/max when they equal the type defaults to reduce noise, OR emit
  explicitly for fidelity — implementer's call, but be deterministic). Run through the formatter
  like other emitted DDL. No `pg_get_sequencedef` exists, so this is reconstruct-from-catalog
  (same approach + minor fidelity bound as tables).

### (b) Serial / identity columns (table emitter)

When introspecting a table's columns, detect the two column-owned-sequence forms and emit the
column so it recreates its own sequence — making column-owned sequences reproducible and the
exclusion in (a) safe:

- **serial**: a column whose `default` is `nextval('<seq>'::regclass)` AND that `<seq>` is
  **owned by this column** (deptype `a`). Emit the column type as `serial` (int4), `bigserial`
  (int8), or `smallserial` (int2) per the underlying type, and **drop** the `nextval` default
  (it's implied). A `nextval` default whose sequence is **standalone** (not owned) is NOT
  serial — keep the column's real type + `DEFAULT nextval(...)` and emit the standalone
  sequence from (a).
- **identity**: a column with `pg_attribute.attidentity = 'a'` (ALWAYS) or `'d'` (BY DEFAULT).
  Emit `<type> GENERATED ALWAYS AS IDENTITY` / `GENERATED BY DEFAULT AS IDENTITY` and drop any
  default. Extend `ColumnDef` to carry the identity generation (e.g. replace the unused
  `is_identity: bool` with `identity: Option<IdentityKind>` where `IdentityKind { Always, ByDefault }`,
  or add such a field — check existing `is_identity` consumers first; it is currently set by
  introspection but not read by the emitter).
- `emit_table`: when the column type is a serial variant, emit just `"name" serial` (skip the
  redundant `NOT NULL`/`DEFAULT`); when `identity` is set, append the `GENERATED … AS IDENTITY`
  clause and skip the default.

## Introspection plumbing

`introspect_tables` and `introspect_sequences` both need the column↔sequence ownership map.
Compute it once (a query over `pg_depend` joining `pg_class` sequences to their owning
`(table, column)` with deptype `a`/`i`), then:
- `introspect_sequences` emits only sequences absent from the owned set.
- `introspect_tables` uses it (plus `attidentity` and the `nextval` default) to mark serial /
  identity columns.

## Testing

- **emit_sequence unit** — a Sequence entity → `CREATE SEQUENCE …` with the expected clauses;
  round-trips through `parse_entity` (or at least is valid for the embedded apply test).
- **emit_table serial/identity unit** — a column flagged serial emits `bigserial` (no
  `DEFAULT nextval`); an identity column emits `GENERATED ALWAYS AS IDENTITY`.
- **Embedded** (feature `embedded-tests`): create a schema with (1) a standalone sequence, (2)
  a table with a `bigserial` PK, (3) a table with a `GENERATED ALWAYS AS IDENTITY` column, (4)
  a column with `DEFAULT nextval('<standalone-seq>')`. Introspect and assert: the standalone
  sequence is captured as `EntityType::Sequence`; the bigserial/identity column-owned sequences
  are NOT captured as standalone; the bigserial column emits `bigserial`; the identity column
  emits the `GENERATED … AS IDENTITY` clause; the standalone-referencing column keeps its
  `nextval` default.
- **Round-trip apply** (embedded): emit the sequence + the serial/identity/standalone-ref
  tables and `execute_script` them into a fresh schema → succeeds (proves self-containment:
  no missing-sequence error, no double-create).

## Edge cases / notes

- `pg_sequences.start_value`/`min_value`/`max_value`/`cache_size`/`cycle` give the attributes;
  the type comes from `pg_sequence.seqtypid::regtype`.
- A standalone sequence referenced by multiple tables is emitted once (its own file); each
  referencing column keeps `DEFAULT nextval(...)`.
- `serial` is sugar — emitting `bigserial` recreates an equivalent owned sequence on apply,
  which is the intended, conventional representation (we deliberately do not preserve the
  auto-generated `<table>_<col>_seq` name; Postgres regenerates it).

## Out of scope

- `ALTER SEQUENCE … OWNED BY` for standalone sequences (standalone seqs have no owner).
- Sequence `last_value`/current position (not schema, it's runtime state).
- This is the final planned reverse-engineer entity patch.
